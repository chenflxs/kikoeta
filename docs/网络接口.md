# 网络接口

最后更新：2026-10-30

本文记录 Kikoeta 的歌词库广播协议、独立 LLS 接入方式，以及客户端使用的听写翻译接口。

## 服务与地址

| 服务 | 默认地址示例 | 用途 |
| --- | --- | --- |
| Kikoeta Transl | `http://127.0.0.1:2370` | Kikoeta 提交听写翻译任务 |
| Kikoeta-LLS 管理页 | `http://127.0.0.1:2376` | 浏览器管理歌词和上传凭据 |
| Kikoeta 广播 / LLS 只读接口 | `http://127.0.0.1:2377` | Kikoeta 导入远程库 |
| Kikoeta-LLS 上传接口 | `http://127.0.0.1:2378` | Transl 上传生成的歌词 |

跨设备访问时把 `127.0.0.1` 换成服务所在设备的 IP 或域名。同一台机器上，Kikoeta 广播与 LLS 默认占用同一端口，不能同时绑定；可关闭客户端广播，或调整 LLS 的 API 端口。

## 歌词库广播（v1）

在设备 A 的“设置 → 歌词与桌面歌词”中开启“歌词库广播”后，应用在 IPv4 的 **2377** 端口提供只读 HTTP 接口。设备 B 可在歌词库的“导入 → 远程库”中输入 A 的地址，例如 `http://192.168.1.20:2377`。

下表中的路径均相对于该地址。接口只接受 `GET`，返回 JSON；广播端只列出本地库中有歌词文件的作品，不转发从其他设备同步的在线作品。当前内置服务使用 HTTP，客户端也接受由外部服务提供的 HTTPS 地址。

| 接口 | 用途 |
|---|---|
| `GET /api/lyrics-library/v1/works` | 获取作品索引 |
| `GET /api/lyrics-library/v1/works/{workId}/files` | 获取一部作品的歌词文件索引，不含文件内容 |
| `GET /api/lyrics-library/v1/works/{workId}/lyrics` | 获取一部作品当前可读取的全部歌词文件内容 |

`workId` 为作品号，接受 `RJ`、`VJ` 或 `BJ` 后接数字；接口会将其转为大写。以下示例中的地址与作品号仅作示意。

### 作品索引

请求：`GET http://192.168.1.20:2377/api/lyrics-library/v1/works`

```json
{
  "version": 1,
  "works": [
    { "workId": "RJ123", "isAi": true, "fileCount": 2 }
  ]
}
```

`version` 是接口版本。`works` 按作品号排序；`isAi` 表示该作品的本地索引中至少有一条 AI 歌词记录，`isTranslated` 表示至少有一条翻译歌词记录（TL），缺省为 `false`；`fileCount` 是歌词/字幕文件数量。没有可用歌词文件的作品不会出现在列表中。

### 作品索引分页

当前客户端默认请求 `GET /api/lyrics-library/v1/works?limit=1000`，随后按 `nextCursor` 继续请求，例如：

```text
GET /api/lyrics-library/v1/works?limit=1000&after=RJ123456
```

| 参数 / 字段 | 说明 |
| --- | --- |
| `limit` | 可选整数，范围 `1–1000`；不传时返回完整索引 |
| `after` | 上一页返回的游标，首次请求省略；使用大写作品号 |
| `nextCursor` | 分页响应额外返回；字符串表示还有下一页，`null` 表示结束 |

作品按作品号字符串排序，不按数字大小排序。内置广播先截取作品索引，再过滤没有歌词文件的作品，所以一页可能不足 `limit` 条，甚至为空；是否继续必须看 `nextCursor`，不能看本页条数。旧服务没有此字段时，客户端把响应当作完整索引，仍可正常导入。

客户端一次同步会顺序读完各页，复用同一个 HTTP 客户端；作品索引等待响应头的超时为 3 分钟，响应体连续 30 秒无数据则超时。文件索引与歌词请求等待响应头的超时为 30 秒。

### 文件索引

请求：`GET http://192.168.1.20:2377/api/lyrics-library/v1/works/RJ123/files`

```json
{
  "workId": "RJ123",
  "files": [
    {
      "relativePath": "disc1/track01.lrc",
      "name": "track01.lrc",
      "extension": ".lrc",
      "isAi": true
    }
  ]
}
```

`relativePath` 是相对于作品索引目录的文件路径，使用 `/` 分隔。`extension` 包含前导点；`isAi` 是该文件所属歌词目录的 AI 标记。`isTranslated` 是该文件所属目录的 TL 标记，缺省为 `false`。TL 文件的路径带有 `RJ号-目标语言/` 前缀，例如 `RJ123-en/disc1/track01.lrc`。缺少语种信息的远程译文使用 `RJ号-tl/` 前缀，避免与原文同名文件冲突。此接口只提供元数据，适合在线库浏览。

### 下载作品歌词

请求：`GET http://192.168.1.20:2377/api/lyrics-library/v1/works/RJ123/lyrics`

```json
{
  "workId": "RJ123",
  "files": [
    {
      "relativePath": "disc1/track01.lrc",
      "name": "track01.lrc",
      "extension": ".lrc",
      "isAi": true,
      "content": "SGVsbG8K"
    }
  ]
}
```

`content` 是文件**原始字节**的 Base64 编码，不是按某种固定字符集转换后的文本。服务端逐个读取该作品的歌词文件；读取失败的文件会从响应中略过。客户端会检查相对路径与支持的歌词扩展名（`.lrc`、`.txt`、`.srt`、`.vtt`、`.ass`、`.ssa`），再把可用文件写入本地歌词库。

### 同步与标记

1. B 可导入多个远程库。每次导入只请求该地址的作品索引（分页读完），并保存作品元数据；尚不下载歌词。`online` 不属于接口响应字段，而是 B 同步时写入本地记录的标记；它与独立的 `isAi`、`isTranslated` 标记可以同时为 `true`。有译文时，作品卡片优先显示「翻译字幕」，歌词库优先显示 TL。
2. 如果 B 的本地歌词库已有同一作品号，跳过该作品的远程索引，不给本地记录添加 `online` 标记。不同远程库的同一作品可以同时留在在线索引中。
3. 导入弹窗中的远程库列表可拖动排序，越靠上优先级越高。B 浏览在线作品文件时调用最高优先级可用来源的 `/files`；播放并匹配歌词时，如果本地没有该作品的歌词文件，则优先向该来源请求 `/lyrics`，失败后尝试较低优先级来源。成功导入本地后移除该作品的 `online` 标记，保留文件的 AI / TL 标记及原文、译文的独立路径。

### 索引刷新

- 进入“在线”页或在“本地 / 在线”之间切换时，不会自动请求远程作品索引。
- 导入远程库时只拉取当次输入的地址；导入弹窗中每个已导入地址旁的刷新按钮只拉取该库。
- 歌词库右上角的刷新按钮在“在线”页会依照列表顺序逐个拉取所有已导入的远程库；没有已导入库时直接显示空列表。
- 客户端同一时间只进行一个作品索引请求，合并同时发往同一地址的请求；同一地址两次索引同步的起始时间至少相隔 2 秒，不同地址的同步至少相隔 300 毫秒；单次同步内部的分页请求按顺序连续发送。手动刷新仍会拉取索引，但不会连续密集请求广播设备。

### 错误与访问范围

| HTTP 状态 | 响应示例 | 含义 |
|---|---|---|
| `400` | `{"error":"invalid_query"}` | 分页参数不合法 |
| `405` | `{"error":"read_only"}` | 使用了 `GET` 以外的方法 |
| `404` | `{"error":"not_found"}` | 路径或操作不存在 |
| `404` | `{"error":"work_not_found"}` | 作品号无效，或本地库没有该作品 |
| `500` | `{"error":"request_failed"}` | 服务端处理请求失败 |

响应使用 JSON，带 `Cache-Control: no-store`。当前广播接口没有身份验证，监听所有 IPv4 地址；请在可信网络中开启，并通过系统防火墙控制可访问的设备。内置服务不提供 TLS，需要 HTTPS 时可在前面配置反向代理。

实现位置：`app/lib/services/lyrics_library_broadcast_service.dart`、`app/lib/services/lyrics_library_remote_client.dart`、`app/lib/services/lyrics_library_service.dart`。

## Kikoeta-LLS 接入

[kikoeta-LLS](https://github.com/chenflxs/kikoeta-LLS) 是独立服务，提供上面的 v1 只读接口和游标分页。Kikoeta 将它作为普通远程库导入，无需专门的客户端模式；本地已有歌词优先、远程库排序和 AI 标记规则保持一致。

远程库地址需要带 `http://` 或 `https://`，不能带账号密码、查询参数或片段。可以使用反向代理路径前缀，例如 `https://example.com/lls`，客户端会追加 `/api/lyrics-library/v1/...`；代理转发到 LLS 时需去掉 `/lls` 前缀。当前客户端不配置远程库认证头，LLS 的管理登录和 Transl 上传凭据不用于读取歌词。

LLS 的 `2378` 上传端口由 Transl 使用：`GET /api/v1/health` 检查服务，`POST /api/v1/lyrics` 上传歌词，支持独立账号密码的 Basic Auth 或密钥的 Bearer Auth。Kikoeta 不直接调用该上传接口。部署、认证与上传格式见 LLS 的 [配置与 API](https://github.com/chenflxs/kikoeta-LLS/blob/main/docs/配置与%20API.md)。

## 听写翻译（Kikoeta Transl）

以下是 `app/lib/services/kt_service.dart` 当前使用的接口，地址相对于用户配置的 Transl 服务（默认本地端口 `2370`）。连接支持 HTTP(S)，要求显式填写端口，客户端随请求附带配置的 Basic Auth 凭据。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/v1/health` | 测试连接 |
| `POST /api/v1/jobs` | 创建听写翻译任务 |
| `GET /api/v1/jobs/{jobId}` | 查询任务状态、进度与产物 |
| `GET /api/v1/jobs/{jobId}/events?after={cursor}` | 增量读取事件，响应含 `events`、`cursor`、`closed` |
| `POST /api/v1/jobs/{jobId}/cancel` | 取消任务 |
| `POST /api/v1/jobs/{jobId}/preempt` | 请求暂停当前任务，供队列插队使用 |
| `POST /api/v1/jobs/{jobId}/resume` | 恢复暂停任务 |
| `GET /api/v1/cache` | 查询已缓存的歌词结果 |
| `GET {download_url}` | 按任务或缓存返回的路径下载歌词 |

创建任务时，`files` 包含音频的 `url`、`name` 和可选 `headers`，由 Transl 获取音频；客户端启用校正与翻译，输出使用 `target_lrc`、`lrc`、非双语。提供作品号和曲目路径时，会附带 `cache.work_id`、`cache.track_paths`。新批次设置 `resume_existing: false`，避免误用其他批次的暂停检查点。

重试会先查询原任务：暂停任务调用恢复接口，仍在执行或已完成的任务沿用原任务；失败、已取消或不存在的任务才重新创建。原任务引用保留提交时的服务器与账号。客户端听写队列仅在当前进程内保留，不保证重启恢复。

实现位置：`app/lib/services/kt_service.dart`、`app/lib/services/dictation_queue.dart`、`app/lib/pages/dictation_translation_page.dart`。服务端完整说明见 [kikoeta-transl](https://github.com/chenflxs/kikoeta-transl)。
